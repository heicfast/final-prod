## ⚠️ Scope (read twice)

**IN SCOPE:**
- **Byte-level and behavioral parity** between og-codebase / RE corpus and our two repos, on every parameter that matters: structure, constants, offsets, enum values, state machines, wire formats, page graph, data flow, error codes, threading model, capability matrix, CLI grammar, session format (ours is CRSF, documented — parity means semantics parity, byte identity with `.rsf`), scan stage model, progress semantics, filter/query data model, recovery writer semantics, health/SMART reporting, preview extraction semantics, RawFixer transactional semantics.

- **Wiring parity:** who calls whom, in what order, with what lifecycle. If og's wizard acquires the device handle in Page 2 and releases at Page 5, and ours acquires at Page 3, that is a finding (unless documented as an improvement).
- **Structural parity:** repository layout, CMake targets, project boundaries, resource organization, localization key conventions (our strings are original; the *structure* of string tables should match og's shape where reasonable).
- **Fixing deviations** found in `core_recovery` and `rda-wizard`, at production grade, with tests, in coordinated commits.
- **Registry of deliberate improvements:** `docs/PARITY-DELTAS.md` in each repo — every divergence, why, and how it is better (or how it is required by licensing/safety/scope).

- New feature development (other agents do this).

- Copying proprietary source verbatim. You re-implement from understanding; you use the RE corpus and decompiled artifacts as *evidence of behavior*, not as code to paste.

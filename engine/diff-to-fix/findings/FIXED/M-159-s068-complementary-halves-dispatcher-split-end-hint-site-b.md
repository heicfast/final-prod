## Summary

The S-068 landing and its N-220 byte-restore fixed the substitution clobber and restored the eager primary re-base — but the machinery has THREE more corpus-decoded halves the landing never carried, one of which its own comments marked undecoded and another its own finding file recorded as "the unmodeled sibling":

1. **The hint's VALUE is the walked END, not the bare first cluster.** The dispatcher computes the dentry's size-derived cluster count BEFORE the walk and stamps `final_first + count` into the hint (:13722-27, :13754-56). The landed code stamps the bare first cluster. The divergence is observable exactly when the anchor's declared size crosses a 64K-cluster bank boundary: the two readings re-base the next torn dentry into DIFFERENT banks — the bare-first reading probes the wrong bank, finds no chain, and the re-base never fires (the file is recovered from wrong-content low clusters or dropped); the END reading finds the true chain.
2. **The failed-but-high arm.** `param_5 != 0 || 0x10000 < local_res8` — the hint keeps the high-water mark even when the walk BROKE, as long as the start sat above 0x10000. The landing's comment called param_5 "undecoded" and implemented success-only. A torn dentry following a broken high anchor finds no hint at all under the landed form.
3. **The dispatcher's ATTR_DIRECTORY routing.** Site A (the eager, ungated re-base) lives in FUN_1800140d0, which the dispatcher routes FILE dentries to; deleted DIRECTORY dentries route to FUN_180014530 — the raw-first, gated-retry population. The byte-restored primary serves directories eagerly with NO gate: below 0x310000 clusters the og never re-bases a directory at all, but the landed code adopts a re-based directory candidate on every volume (a divergence the byte-restore inherited from the original S-068 landing, never decoded until the dispatcher read).
4. **Site B itself.** The raw-first retry leg with the 0x310000 gate, the write-back, and the adopted-cluster hint update (:14826-48) — the "unmodeled sibling" the N-220 finding recorded as the next step. Above the gate (every volume > 0x310000 clusters — 12.8 GiB at 4 KiB clusters, i.e. most modern disks), a deleted directory with a torn high word recovers through the retry in the og and not at all in the core.

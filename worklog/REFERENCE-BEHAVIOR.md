## Elevation & privilege

- **DRW.exe (DRWLoader, the product's Windows entry point) ships `requireAdministrator`**: embedded manifest in .rsrc — `re-workspace/reversed/DRW.exe/strings_ascii.txt:355` (`<requestedExecutionLevel level='requireAdministrator' uiAccess='false' />`), byte-dump at `DRW.exe/rabin2_strings_data.txt:1183`.
- **DRWUI.exe (main UI) is also `requireAdministrator`**: `re-workspace/reversed/DRWUI.exe/strings_ascii.txt:41023` + `rabin2_strings_data.txt:1728`; direct launch is not a supported path anyway — DRWUI renders zero windows without the loader (`re-workspace/artifacts/UIUX/dynamic-ground-truth--window-census-verification.md` §2).
- **Launch chain**: DRW.exe `CreateProcessA("DRWUI", inheritHandles=TRUE)` at DRW_decompiled.c:2521 — the elevated token is inherited, so no second UAC (`re-workspace/artifacts/DRW-exe--launcher.md:31`). Loader = windowless supervisor with crash-restart loop (max 1 auto-restart, `1 < uVar17` guard, :63) and 5s log-flusher.
- **UAC therefore appears once, at DRW.exe launch** (manifest-triggered). No corpus doc captures the actual UAC prompt (dynamic runs used admin CI runners); no `ShellExecute`/`runas` verb anywhere in `ghidra-core/DRW_decompiled.c` (rg negative) → **no restart-as-admin flow exists**.
- **DRWService.exe** (BitLocker FVE key service): manifest `asInvoker` (`re-workspace/reversed/DRWService.exe/strings_ascii.txt:201`) but installed via `CreateServiceA` as `"Read FVE Server"`, `SERVICE_WIN32_OWN_PROCESS`, `SERVICE_AUTO_START` → runs as **LocalSystem without UAC** (`re-workspace/artifacts/DRWService-exe--bitlocker-service.md:11-18`, which also states it exists "so a standard-user DRW instance can obtain the keys without UAC" — note the tension with DRW.exe's requireAdministrator manifest; both facts are cited as-is).
- **SetupUE.exe (install bootstrap) = `asInvoker`** (`re-workspace/reversed/SetupUE.exe/strings_ascii.txt:354`); it gates on a 16-OS table, then hands off to the Inno Setup wizard (`re-workspace/artifacts/Installer/setupue-infoforsetup--bootstrap-pair.md:11-15`). The outer Inno wrapper that would carry the installer's elevation is not in the corpus.
- All other binaries (engine DLLs, repair/viewer exes, DRWReport, EuDownloader, DRWService, EUinApp…) are `asInvoker` — they inherit the elevated parent's token (e.g. `re-workspace/reversed/ZfsSearchDLL.dll/strings_ascii.txt:644`, `EuRepairHost.exe/strings_ascii.txt:81`, `EuDownloader.exe/strings_ascii.txt:8163`).
- In-app "admin" strings are **NAS/Linux SSH credentials**, not local elevation: "Administrator account required" / "Password of Administrator" / "Account without sufficient permission. Try with your Administrator account." (`re-workspace/reversed/DRWUI.exe/strings_ascii.txt:12678,13151-13152`, NAS-connect context).
- Elevation is functionally required: raw sector IO via `\\.\EPRDTDRV` kernel driver (`architecture/04-recovery-workflow.md:76-78`) and `fsutil behavior set` TRIM toggling (below) both need admin.

## Disk health surface

- **Disk health is a separate companion app**, not a DRWUI page: `DiskHealth.exe` (internal name **DiskSmart**), **CrystalDiskInfo lineage** (CAtaSmart/DiskInfoMgr/CTrayIcon + USB bridge tables), Qt Quick/QML, frameless **840×590**, tray-resident — `re-workspace/artifacts/DiskHealth/diskhealth--smart-companion.md:9-12`, `UIUX/19-diskhealth-quick-ui.md:6-11`.
- **What it shows**: per-disk health card (states "Good" / "Caution!" / "Normal" / "Your disk may have a physical failure:") + **S.M.A.R.T. attribute table: ID / Attribute / Current / Worst (ST) / Threshold / RawValue / Status + "Temprature" [sic]**; disk selector "Which disk do you care about?" / "Disk %1"; CautionWidget with "View Solutions"; "Launch Disk Health" entry — `UIUX/19-diskhealth-quick-ui.md:26-28`.
- **Engine**: `CAtaSmart` multi-transport SMART polling (SAT/ATA passthrough, CSMI for Intel RST, NVMe-Realtek), USB bridge tables (ASM1352R etc.), `RefreshThread` background poller, NVMe + virtual-disk ("Parallels Virtual NVMe Disk") awareness — `diskhealth--smart-companion.md:19-23`.
- **In DRW itself**: no SMART page; SSD/TRIM awareness appears as the home-row **"TRIM OFF/ON" chip** (recovery-chance indicator) — `UIUX/07-home-phase-deep-dive.md:17`; DiskHealth is reachable as a More-Recovery-Tools card (`35-redesign-reference-atlas.md:144`).
- **DRWUI DOES spawn processes** (runtime-proven): shells out to **`fsutil.exe`** — `GetSystemDirectoryA + "%s\fsutil.exe"`, `CreatePipe`+`CreateProcessA` (hidden, `WaitForSingleObject(10000)`), output parsed after `"= "` into **tri-state global `DAT_141ba9514`** (−1 unknown / 1 TRIM on / 0 TRIM off) — `re-workspace/artifacts/UIUX/24-dynamic-ground-truth-ingestion.md:113`, decompile at `re-workspace/reversed/ghidra-drwui/DRWUI_decompiled.c:178678-178767`; command strings " behavior query disabledeletenotify" / "%s\fsutil.exe" at `DRWUI.exe/strings_ascii.txt:35319-35321`.
- **TRIM write-toggle flow**: at scan start on an SSD target → `FUN_1400c9450(0)` = `fsutil behavior set disabledeletenotify 1` (**TRIM disabled during scan**); `CScanMgr::doExit` → `FUN_1400c9450(1)` = `set disabledeletenotify 0` (**TRIM re-enabled on exit**) — `DRWUI_decompiled.c:178768-178790` (setter), `:314214/314224` (scan start), `:315408` (doExit), strings `:35322-35323`.
- **PowerShell Get-PhysicalDisk: display copy, not an executed probe.** DRWUI contains `PowerShell "Get-PhysicalDisk | Format-Table -AutoSize"` and `wmic DISKDRIVE` as tr-wrapped strings built by string-builder functions (`DRWUI_decompiled.c:365727/365769`) with no CreateProcess site and no resolved caller — troubleshooting/support text; only 2 case-insensitive "powershell" hits in 2.38M decompiled lines. `DRWUI.exe/strings_utf16.txt:13920-13922`.
- BitLockerLib's PowerShell `manage-bde` fallback is a separate, engine-side elevation path (`architecture/02-kernel-driver-architecture.md:114`).

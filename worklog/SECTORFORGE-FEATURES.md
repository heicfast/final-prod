## 1. Architecture overview
Data flow: **device → image+map → scan → files/extract | carve**.
1. `BlockDevice` trait — sector-aligned, all-or-nothing reads (`block_device.rs:9-30`); impls: `WindowsPhysicalDrive`, `LinuxBlockDevice`, `FileBlockDevice` (image), `FakeBlockDevice` (tests, bad-range simulation + read counter).
2. `Imager<D: BlockDevice, W: Write+Seek>` — two passes; every byte-range outcome recorded in an in-memory `MapFile` checkpointed to disk every 5 s (`imager.rs:51-99`; `CHECKPOINT_INTERVAL` `sf-cli/src/lib.rs:23`).
3. `partitions::scan` — MBR/GPT + optional whole-disk signature scan → `Vec<PartitionInfo{start_bytes, size_bytes, filesystem, confidence, source, label}>` (`partitions.rs:45-59,221-267`).
4. `SafeReader` — recovery reads never abort: map holes and read errors become zero-fill + an unreadable-byte count (`reader.rs:1-8,104-239`).
5. Filesystem readers `Ntfs`, `Fat`, `Ext` implement `trait Volume { fn index(&mut self, …) -> Index; fn copy_file(…) }` (`ntfs/extract.rs:36-44`) producing one shared `Index` (id → `IndexEntry{seq, in_use, is_dir, parent_ref, name, size, created, modified, recoverable}`, `ntfs/mod.rs:35-46`).
6. `sf-cli` is the only engine binary the GUI runs: `--json` emits an NDJSON event stream (contract v2; `CONTRACT_VERSION = 2`, `sf-cli/src/lib.rs:22`; spec `docs/cli-contract.md`). The GUI "never links sf-core" (`gui/src-tauri/src/cli.rs:1-2`). On Windows the engine is compiled into the GUI exe, which runs *itself* as the child via `SectorForge.exe sf-cli <args>` (`gui/src-tauri/src/main.rs:6-9`; `EMBEDDED_ARG`/`ENGINE_EMBEDDED`, `cli.rs:214-227`). On Linux a static sidecar runs under `pkexec` when a `/dev/` source needs root (`cli.rs:282-356`).
7. Safety invariant: in device mode the CLI refuses any output (`--dest`, `--map`, `--out`) that resolves onto the source physical disk, or whose backing disk cannot be determined (`drives/mod.rs:80-104`; applied `sf-cli/src/lib.rs:397`, `recover.rs:58-63,108,297`).
8. Job orchestration: one `Slot` (Arc<Mutex<Option<(run_id, Child)>>>) per job kind (image/scan/carve/files/extract/hash/survey); run-ids prevent a finished run's reader thread from claiming a newer process; stderr drained to EOF with a 16 KiB tail kept for error reporting (`gui/src-tauri/src/cli.rs:380-466`).

## 2. Feature inventory

### 2.1 ddrescue-style two-pass imaging
**Behavior.** Pass 1 ("copy") sweeps forward in large chunks, skipping past damage to maximize rescued data fast; pass 2 ("retry") binary-splits every damaged region down toward individual sectors, retrying each up to N times before declaring it genuinely bad. Every outcome lands in the mapfile so a run stops/resumes anywhere.

**Sources.** `crates/sf-core/src/imager.rs` (whole file); CLI wiring `sf-cli/src/lib.rs:396-492`; defaults `imager.rs:31-40`.

**Algorithm.**
- `ImagerConfig` defaults: `initial_chunk = 1 MiB`, `skip_size = 1 MiB`, `max_retries = 3`, `reverse = false` (`imager.rs:33-39`). CLI flags `--chunk-size --skip-size --retries --retry-only --reverse` (`sf-cli/src/lib.rs:66-80`).
- Pass 1 `run_copy_pass` (`imager.rs:138-180`):
  - `pos = align_down(map.current_pos, sector)`; loop `map.find_next(pos, &[NonTried])`, falling back to `find_next(0, …)` so a resumed run (or one that last ran in reverse) picks up untried areas *before* current_pos (`imager.rs:148`).
  - `chunk_len = align_chunk_len(min(initial_chunk, avail), sector)`; read into an `AlignedBuf`.
  - Success → `write_chunk` (seek+write_all at pos) then `map.mark(pos, chunk_len, Finished)`.
  - Failure → mark `skip = align_chunk_len(max(skip_size, chunk_len), sector).min(avail)` bytes `NonTrimmed` and jump past: "one bad spot can't stall the rescue of everything after it" (`imager.rs:164-171`).
  - Per chunk: `map.current_pos/current_status` updated, `checkpoint(false)`, progress callback.
- Reverse pass 1 `run_reverse_copy_pass` (`imager.rs:184-222`): mirrors with `find_prev`; `current_pos` stores the *lowest* point reached (0 = fresh map). Reading a damaged area "from the other side often gets more of it" (`imager.rs:26-28`).
- Pass 2 `run_retry_pass` (`imager.rs:228-241`): iterate `find_next(0, &[NonTrimmed, NonScraped])` → `split_and_retry` (`imager.rs:243-284`):
  - Whole-region read succeeds → `Finished`.
  - Fails at `len <= sector` → retry same sector while `attempt+1 < max_retries`, else `BadSector`.
  - Fails at larger len → mark `NonScraped`, split into sector-aligned halves (`half = align_chunk_len(len/2, sector).min(len - sector)`), recurse each.
  - Checkpoint + progress fire *inside* a damaged region because "each failed read on a dying drive can take seconds" (`imager.rs:269-272`).
- Alignment: all offsets/lengths multiples of `sector_size` — a hard direct-I/O requirement enforced trait-wide (`block_device.rs:9-14`); `align_chunk_len` rounds down but never below one sector so a single sector can always be attempted (`imager.rs:291-296`).

**MAP PERSISTENCE / RESUME.**
- Checkpoint at least every 5 s and at each pass end (`imager.rs:75-99`; `CHECKPOINT_INTERVAL` `sf-cli/src/lib.rs:23`) — "killing the program can't [lose progress]: at most the last 5 seconds are redone" (`README.md:198-199`).
- `dest.flush()` before `map.save()` so image data reaches the OS before the map claims it is rescued (`imager.rs:87-88`).
- A failed *periodic* save (AV/indexer/sync lock) is swallowed — "aborting a recovery over it would be far worse"; forced saves propagate the error (`imager.rs:90-96`).
- Save is atomic: write `<name>.tmp`, `sync_all`, rename; rename retried up to 5×50 ms on `PermissionDenied` (Windows replace-while-open) (`mapfile.rs:212-238`).
- Resume (`run_image`, `sf-cli/src/lib.rs:402-434`): map exists → load; **refuse** if map size ≠ source size ("wrong map for this source?"); **refuse** if map has Finished bytes but `--dest` is missing or a different size ("Resuming would leave those parts of the image empty"). Fresh runs write the initial all-`NonTried` map immediately (`lib.rs:429-433`).
- Reverse runs mark the destination sparse (`FSCTL_SET_SPARSE`) so the first write at the end doesn't zero-fill the whole image; best-effort on FAT/exFAT (`device/mod.rs:18-29`; `lib.rs:446-453`).

**UX behavior.** `start` event carries `resumed`; `pass_start{name: copy|retry}`/`pass_complete`; `progress` throttled to 200 ms (`PROGRESS_INTERVAL` `lib.rs:24`; `report_progress` `lib.rs:350-376`); human mode prints one `\r` line (`pct% rescued … bad … pending … pos 0x…`). Pause = kill the process; the map survives (`docs/cli-contract.md:29-32`). GUI: Start/Pause buttons, "Resume" label when a partial map exists (`gui/src/screens/ImageScreen.tsx:93-101`); tiles Rescued/Bad/Pending/Current pass; 1000-cell health map colored by worst status per equal slice (`gui/src/components/HealthMap.tsx:6-33`) fed by 1 Hz `status --map` polling (`gui/src/store/actions.ts:107-122,159-162`); presets Healthy (4 MiB/1 retry), Some bad sectors (default 1 MiB/3), Badly damaged (64 KiB reads/16 MiB jumps/1 retry/5 s timeout), Thorough (128 KiB/8 retries/30 s) (`gui/src/store/image.ts:53-78`); "What happens when you press Start" 3-step explainer (`ImageScreen.tsx:108-121`).

**Prerequisites.** Raw mode needs Administrator (Win) / root or `disk` group (Linux); a permission-denied open gets a tailored hint (`lib.rs:226-236`). Map viewer can hand any old map back to the Image screen for Resume or Retry-bad-areas (`gui/src/screens/MapViewScreen.tsx:33-40,95-98`).

**Tests.** `imager.rs:309-439` (6): clean device fully rescued; two-sector bad patch isolated to exactly `BadSector == 1024` bytes with everything else Finished; mid-pass on-disk map observed from inside the progress callback (killed-run resume); reverse reads the last chunk first and still isolates; forward run picks up untried areas a reverse run left before current_pos; resume does not redo finished work (destination untouched in finished region). Loop-device E2E (ignored; `tests/linux_loopdev.rs:12-45`): O_DIRECT size/sector queries, unaligned SafeReader reads, full two-pass image compared byte-for-byte.

**Edge cases.** Untried holes before `current_pos` (wrap-around); zero-size maps; `align_chunk_len ≥ sector`; reverse + sparse file; FAT/exFAT dest cannot be sparse (slow start only); 5 s progress window loss on power cut only (`README.md:198-199`).

### 2.2 The mapfile (ddrescue-compatible)
**Behavior.** Resumable per-range status record; on-disk format "deliberately close to GNU ddrescue's mapfile" so an interrupted run resumes and `ddrescueview` can open it (interop = CLAIM, `mapfile.rs:1-6`, `README.md:110-111`; format itself verified in code).
**Sources.** `crates/sf-core/src/mapfile.rs`.
**Algorithm.**
- `Status` → char: NonTried `?`, NonTrimmed `*`, NonScraped `/`, BadSector `-`, Finished `+` (`mapfile.rs:29-48`).
- In-memory: sorted, non-overlapping, contiguous `Vec<Block{pos,size,status}>` covering `[0,size)`; `mark()` splits/carves holes and `merge_adjacent()` re-joins same-status neighbors (`mapfile.rs:126-164,321-333`); panics if a range runs past device size (`mapfile.rs:131`).
- `find_next(from, statuses)` / `find_prev(before, statuses)` clip results to the boundary (`mapfile.rs:168-189`).
- Serialization (`to_ddrescue_string`, `mapfile.rs:191-210`): `#` comments, `current_pos current_status` line (`0x%X  status`), then `0x%08X  0x%08X  status` block lines.
- Parser `from_ddrescue_str` (`mapfile.rs:245-311`): skips blanks/comments; header line then block lines; hex fields accept optional `0x`/`0X` (`mapfile.rs:313-319`); errors carry line numbers and reasons; device size inferred from the last block's end.
**UX.** `sf-cli status --map M --json` emits one event with `size`, `current_pos`, per-status totals and the full block list — what the GUI health map renders; the file is replaced atomically at each checkpoint so polling is safe (`docs/cli-contract.md:81-93`).
**Tests.** 8 (`mapfile.rs:335-443`): fresh map single block; mark split/merge; hole carving; find_next/prev clipping; bytes_with_status; text round-trip incl. current_pos; on-disk round-trip.

### 2.3 Fault-tolerant recovery reads (`SafeReader`) — the "honest partial" layer
**Behavior.** `files`/`extract`/`carve` never give up on a read error: unreadable bytes come back zero-filled and *counted*, so results can say "partial" instead of silently containing blanks (`reader.rs:1-8`). Map holes are unreadable *without touching the device* — "on a failing drive re-reading them is wasted wear" (`reader.rs:6-8`).
**Sources.** `crates/sf-core/src/reader.rs`.
**Algorithm.**
- `RangeSet`: sorted merged half-open ranges with `insert/bytes_in/intersecting` (`reader.rs:20-78`).
- `unreadable_from_map(path, source_size)`: every block not `Finished`; **refuses** a map whose size ≠ source ("Wrong map for this source?", `reader.rs:83-94`).
- `SafeReader::read(offset, out)` (`reader.rs:154-199`): zero-fill; compute the sector-aligned envelope (`MAX_READ = 4 MiB`, `BUF_ALIGN = 4096`, `reader.rs:16-17`); subtract known-bad + found-bad ranges; read the good parts in ≤4 MiB aligned pieces; past-the-end counts as unreadable; returns the unreadable byte count.
- `read_split` (`reader.rs:211-238`): failed reads binary-split in half down to `granularity` (default = sector size; `with_granularity` rounds up to sector multiples).
- Carving a live device uses `CARVE_DEVICE_GRANULARITY = 64 KiB` — "give up on 64 KiB at a time rather than retrying every sector (the imager is the tool for squeezing out every sector)" (`recover.rs:19-22,120-122`).
**UX.** The GUI auto-attaches the imaging map when the recovery source equals the Image screen's destination (case-insensitive, slash-normalized path compare, `gui/src/lib/recoverlogic.ts:5-13`; `store/actions.ts:211-215`) and explains it: "Using the map from the Image screen, so files that overlap bad sectors are shown as partial…" vs the no-map warning (`RecoverScreen.tsx:104-124`).
**Tests.** 5 (`reader.rs:241-303`): RangeSet merge/measure; unaligned read matches device; bad sectors zeroed + counted + `is_unreadable`; map holes unreadable without reading; past-end.

### 2.4 Partition detection
**Behavior.** MBR incl. extended/logical chains; GPT CRC-verified with backup-header fallback; no-table "superfloppy" volumes at sector 0; whole-disk signature scan for partitions the table no longer lists.
**Sources.** `crates/sf-core/src/partitions.rs`.
**Algorithm.**
- `detect_filesystem_at(buf)` (`partitions.rs:69-94`): NTFS = OEM `NTFS    ` **and** BPS ∈ {512,1024,2048,4096}; exFAT = `EXFAT   ` + cluster shift 9..=12; FAT12/16/32 = `0x55AA` + jump `0xEB|0xE9` + valid BPS + `FATxx` label at 54/62/82; ext = magic `0xEF53` at 1024+56 with rev ≤ 6. `DETECT_WINDOW = 1088` bytes (`partitions.rs:61-63`).
- `volume_size_bytes` (`partitions.rs:98-121`): NTFS `(total_sectors+1)×BPS` (the +1 covers the backup boot sector); FAT 16/32-bit totals; exFAT `cluster_count << shift`; ext `blocks × (1024 << log_block_size)`.
- MBR (`partitions.rs:134-152`): 4 entries at 446; extended types `0x05/0x0F/0x85`; EBR chain (`read_logical_partitions`, `284-302`): first entry relative to its EBR, second points to the next EBR relative to the extended base; `seen` HashSet + 256-EBR cap breaks loops.
- GPT (`partitions.rs:163-216,304-333`): header CRC-32/IEEE (own implementation, `crc32` `partitions.rs:442-451`) verified with the CRC field zeroed; sanity: `num_entries` 1..=1024, `entry_size` 128..=4096 and %8==0; **primary corrupt → backup header at last sector**; zero-type-GUID entries skipped; label read as UTF-16.
- `scan()` order (`partitions.rs:221-267`): filesystem-at-sector-0 check **before** MBR parsing (a superfloppy boot sector also ends `0x55AA` and would be mistaken for an MBR, `partitions.rs:228-241`); `0xEE` protective entry → GPT; per-partition boot sector unreadable/unknown → `LowConfidence`, never an abort (`table_partition`, `335-359`); `deep || partitions.is_empty()` adds signature-scan results, dedup by `start_bytes`, sort by start.
- `signature_scan` (`partitions.rs:365-407`): 4 MiB chunks (`SIGNATURE_SCAN_CHUNK`), over-reading `DETECT_WINDOW` so a filesystem starting in the last sector of a chunk is recognized; on a hit, `skip_until = start + volume_size` so a volume's contents and its backup boot sector aren't reported as more partitions; unreadable chunks skipped, not fatal; progress callback per chunk.
- Confidence taxonomy (`partitions.rs:20-29`): `Confident` (valid table + known FS), `Rebuilt` (signature-scan only), `LowConfidence` (table entry, unknown boot sector).
**UX.** CLI `scan --deep` ("to find partitions missing from (or deleted from) the partition table", `lib.rs:88-95`); `survey` = parallel quick scan of N sources, one thread each, per-source `survey_result`/`survey_error`, never fails as a whole (`lib.rs:96-101,513-535`); GUI runs the survey at startup for every drive when elevated, skipped otherwise to avoid a boot-time password prompt (`gui/src/store/actions.ts:71-84`).
**Tests.** 12 (`partitions.rs:453-700`): CRC known vector; each FS + size; NTFS with nonsense BPS rejected; MBR primary + logical; low-confidence entry; GPT with label; backup-header fallback; superfloppy not mistaken for MBR; wiped table (NTFS backup boot not double-reported; ext superblock in a chunk's last sector found only via over-read); deep scan finds a table-less FAT32; signature scan survives an unreadable region; `read_up_to` unaligned/past-end.

### 2.5 NTFS deleted-file recovery
**Behavior.** Reads the MFT directly: deleted files, fragmented files, sparse files, hard links via `$ATTRIBUTE_LIST`; rebuilds full paths; checks whether a deleted file's space was reused (`README.md:120-124` — CLAIM verified in code). Compressed/encrypted files are listed and flagged but not decoded (`README.md:184-185`).
**Sources.** `crates/sf-core/src/ntfs/{record,runlist,volume,mod}.rs`; tests `ntfs/tests.rs` (7) + `tests/ntfs_fixture.rs`.
**Algorithm.**
- Boot validation (`volume.rs:22-48`): BPS ∈ {512,1024,2048,4096}; sectors/cluster 1..=0x80 or `2^(256-n)`; cluster size power-of-two ≤ 2 MiB; record size 512..=65536 and %512==0; `mft_lcn × cluster_size < total`.
- MFT bootstrap (`volume.rs:94-115`): record 0 (`$MFT`) read from `mft_lcn`, falling back to `mftmirr_lcn` (the mirror holds the first records); if record 0 has `$ATTRIBUTE_LIST`, a very fragmented MFT is completed through it; a lost extension record truncates `mft.size` to what is locatable instead of failing.
- Update-sequence fixups (`record.rs:19-45`): "FILE" magic; `usa_count-1 == record_len/512`; USN must match at every 512-byte sector tail; **an all-zero sector is explicitly rejected** (unreadable sectors come back as zeros and would otherwise pass a zero USN). Records failing fixups are skipped, not half-trusted (`volume.rs:152-167,172-185`).
- Record header (`record.rs:82-107`): `in_use = flags & 1`, `is_dir = flags & 2`, `base_ref` for extension records; attribute walk requires `len ≥ 16`, `len % 8 == 0`, bounds-checked; any violation rejects the whole record.
- Attributes (`record.rs:109-143`): resident (value offset+length) and non-resident (`start_vcn`, runlist offset, `data_size`, `init_size`); flags `0x0001` compressed, `0x4000` encrypted (`record.rs:13-14`).
- Runlist decode (`runlist.rs:14-47`): 4-bit length/offset field counts (≤ 8 each), signed LCN deltas, sparse runs (`lcn = None`), terminator required; malformed → None.
- Name selection: all `$FILE_NAME` attrs parsed; `namespace_rank` prefers Win32/Win32+DOS (ns 1|3) over POSIX (0) over the 8.3 DOS alias (2) (`record.rs:154-181`, applied `volume.rs:203-210`). Timestamps from `$STANDARD_INFORMATION` with `$FILE_NAME` fallback (`volume.rs:211-215`).
- `$ATTRIBUTE_LIST` resolution (`volume.rs:234-273`): an extension record is adopted **only if it points back at the base** (`base_ref` record number AND sequence AND the list entry's seq match the record's) — after deletion the extension record may have been reused by another file; missing pieces set `incomplete`.
- `DataStream` assembly (`volume.rs:275-319`): unnamed `$DATA` fragments sorted by `start_vcn`; VCN gaps or coverage short of `init_size` → `incomplete`; sparse runs preserved (`lcn=None` reads as zeros, `volume.rs:131-150`); `init_size` clamped to `data_size`.
- **Deleted detection** = `!in_use` (MFT flags bit 0). **Parent resolution** (`ntfs/mod.rs:130-137`): parent accepted when `p.seq == pseq`, or — for a deleted parent — exactly `pseq.wrapping_add(1)` (deleting bumps the sequence); anything else means the parent record was reused; parent must be a directory and not the record itself.
- `ancestry()` (`ntfs/mod.rs:139-156`): walks to root (record 5) with a 4096-cycle guard, yielding `Rooted(ids)` or `Orphaned(ids)`; `path()` builds `/`-joined paths, `None` for orphans (`159-174`). `is_listed` excludes records < 16 (`FIRST_USER_RECORD`, NTFS metadata) and anything under `$Extend` (record 11) (`ntfs/mod.rs:22-25,176-185`).
- `Index::build` (`ntfs/mod.rs:70-105`): batches of 1024 records (`BATCH`) read in one sweep each (`for_each_record` — "much faster than one read per record on a big MFT", `volume.rs:169-185`); progress per batch; extension records (base_ref ≠ 0) skipped; recoverability assessed per file.
- `assess` (`ntfs/mod.rs:198-221`): dirs → Full; resident/empty → Full; compressed/encrypted → Partial; else `damage()` = (total, unreadable, reused) over the runlist — unreadable via `SafeReader`, reused via `$Bitmap` set bits (deleted files only); `lost ≥ total` → None, `lost > 0 || incomplete` → Partial. `$Bitmap` (record 6) unreadable bits read as **allocated** so "a deleted file is never called 'full' on the strength of unreadable evidence" (`volume.rs:321-344`).
- `copy_stream` (`volume.rs:369-392`): 4 MiB chunks; bytes past `init_size` written as zeros ("Past the valid data length NTFS defines the contents as zero").
**UX.** `files` emits per-entry `id, parent_id, name, path, is_dir, size, deleted, modified, created, recoverable` (`recover.rs:247-253`); orphans print as `<orphaned>/name` in human mode (`recover.rs:261`).
**Tests.** Hand-built hostile volume (`ntfs/tests.rs:209-296`) covering: fragmented MFT; torn record skipped; reused parent → orphan; reused clusters → `Recoverable::None`; deleted folder with sequence-bumped parent resolving to `/Old/x.txt`; DOS alias losing to the Win32 name; `$ATTRIBUTE_LIST` data in extension record 27; sparse run read as zeros; compressed flag → Partial + empty file with note; map hole → Partial; MFT-mirror fallback for a torn `$MFT` (`tests.rs:306-353`). Real Windows-formatted VHD (`tests/ntfs_fixture.rs:31-91`): every recovered file byte-compared via SHA-256 against a manifest; hard links exercising `$ATTRIBUTE_LIST`; deleted folder tree recreated.

### 2.6 FAT12/16/32 + exFAT recovery
**Sources.** `crates/sf-core/src/fat/{mod,dir}.rs`; tests `fat/tests.rs` (5).
**Algorithm.**
- FAT kind from cluster count: <4085 → FAT12, <65525 → FAT16, else FAT32 (`fat/mod.rs:137-141`).
- FAT table load with **per-sector copy fallback** (`load_table`, `fat/mod.rs:182-241`): an unreadable sector of the first FAT is re-read from the next copy (up to `nfats`); if all copies fail it is filled `0xFF` = end-of-chain = allocated ("damage never makes a file look better than it is", `fat/mod.rs:6-8`).
- Live chains: `chain()` follows the table with run merging and a loop cap of cluster count (`fat/mod.rs:260-277`).
- **Deleted FAT files are read as one contiguous run from their first cluster** (FAT zeroes the chain on delete); reused clusters counted via FAT entry ≠ FREE (or the exFAT bitmap) (`runs()` fallback `fat/mod.rs:280-297`; `damage()` `334-346`). Fragmented deleted files come back with other data in later parts — flagged, not hidden (`README.md:187-188,194-195`).
- LFN assembly (`dir.rs:51-81`): live entries validated by checksum + ordinals; deleted entries (first byte `0xE5`, real first character gone) accepted on agreeing LFN checksums only; deleted 8.3 first char becomes `_` (`dir.rs:42`).
- Deleted directories: at most `DELETED_DIR_CLUSTERS = 64` free clusters read (`fat/mod.rs:29-30,373-379`); parsing is **strict** — must begin with the `.` entry and stops at the first implausible entry (`dir.rs:86-89,106-110`); entries pointing outside the cluster heap are garbage and skipped (`fat/mod.rs:436-438`); a deleted exFAT dir whose first cluster is reallocated yields nothing (`fat/mod.rs:381-383`).
- exFAT (`fat/mod.rs:154-178`, `dir.rs:128-191`): boot sanity (BPS shift 9..=12, ≤2 FATs); file entry sets validated by `set_checksum` computed **as if bit 7 of each type byte were set** (deleting clears it); `NoFatChain` contiguous flag; valid-data-length zero-fill; allocation bitmap located from root entry type `0x81`.
- Timestamps: FAT stores local time with no zone; shown as UTC (`timefmt.rs:28-31`; `README.md:190`).
- Same `Index`/`Volume` contract as NTFS: BFS directory walk from root id 5, `parent_ref = dir_id`, ids assigned from 16 up — "only stable for the same, unchanged source" (`docs/cli-contract.md:208-212`).

### 2.7 ext2/3/4 recovery
**Sources.** `crates/sf-core/src/ext/mod.rs`; tests `ext/tests.rs` (1).
**Algorithm.**
- Superblock at +1024: magic `0xEF53`, rev ≤ 6, geometry sanity, `INCOMPAT_64BIT`, `meta_bg` + `sparse_super` descriptor placement (`ext/mod.rs:95-158`); external journal devices rejected (`ext/mod.rs:104-106`).
- File maps (`ext/mod.rs:191-291`): extent trees (`0xF30A` node magic, depth ≤ 5, ≤ 2^16 nodes, extents > 32768 = preallocated → skipped) or ext2 direct + 1/2/3-level indirect blocks; extents past the volume → `incomplete`; inline data only the first 60 bytes (rest lives in an xattr — flagged incomplete).
- **Deleted names from directory slack**: after each live entry's used bytes, candidate deleted entries are validated (inode ≤ max, rec_len sane, no NUL/slash in name, filetype 1..7 when FILETYPE) (`parse_dir`/`deleted_entry`, `ext/mod.rs:379-429`); hashed (htree) directories' `..`/empty-entry index blocks are not slack (`ext/mod.rs:397`).
- A deleted name whose inode still has `links != 0` is a rename leftover / reuse → skipped (`ext/mod.rs:478-480`); symlinks/devices/sockets/fifos skipped (`481-484`).
- ext3/4 deletion wipes block pointers → listed "none" with the note "Its block pointers were wiped when it was deleted (ext3/ext4 do this)… try carving instead" (`ext/mod.rs:519-521`). fscrypt files copied still encrypted with a note (`541-543`).
- Block-bitmap reuse detection per group; unreadable bitmap blocks = allocated (`ext/mod.rs:317-350`).

### 2.8 File carving
**Behavior.** PhotoRec-style signature scan at sector boundaries; each file's end is found "from its own structure rather than guessed" (`README.md:139` CLAIM, verified). Type count: README says "About 95 file types" (`README.md:135`); the `TYPES` registry contains exactly **94** ids (counted, `carve/formats.rs:83-178`).
**Sources.** `crates/sf-core/src/carve/{mod,probe,formats}.rs`; tests `carve/tests.rs` (14) with synthetic builders for jpg/png/gif/pdf/zip/mp4/sqlite/7z/rar4/rar5/ole/rtf/ps/djvu/chm and more.
**Registry structure.**
- Two-level: 51 parser `Kind`s (`Kind::ALL`, `formats.rs:181-233`) → 94 user-facing ids via `Kind::type_ids()` (`formats.rs:236-291`).
- One Kind fans out to many ids: `Zip → [zip, docx, xlsx, pptx, vsdx, xps, odt, ods, odp, odg, epub, jar, apk, 3mf]`; `Mp4 → [mp4, mov, m4v, 3gp, m4a, heic, avif, cr3]`; `Tiff → [tif, cr2, nef, arw, dng, orf, rw2]`; `Ole → [doc, xls, ppt, msg, ole]`; `Riff → [avi, wav, webp]`; `Exe → [exe, dll]`; `Font → [ttf, otf]`; `Regf → [dat]`.
- `TYPES: &[TypeInfo{id, description}]` is the `--list-types` surface (`formats.rs:73-178`).
**Identification depth (magic-only vs structural).** Every signature in `identify()` (`formats.rs:345-541`) validates structure beyond a short magic, because "each one validates more than a short magic" is required — every signature also ends the previous unknown-length file (`formats.rs:342-344`). Examples: PNG needs `IHDR` at offset 12; JPEG `FF D8 FF` + marker ≥ 0xC0 and ≠ 0xFF; OLE checks sector-shift and minor version (3/9 or 4/12); zip `PK\x03\x04` + version < 100; MP4 `ftyp` box size 16..=512, %4, printable brand; xz verifies CRC-32 of the stream flags; ELF checks machine 1..=4 and type 1; WOFF checks table-directory search fields derived from the table count; regf verifies a 127-dword XOR checksum; tar verifies the header checksum; TS needs 5 consecutive 188-byte (or 4×192-byte) sync bytes; FLV exact header lengths; MP3 ID3 tag sanity; MIDI header length == 6, format ≤ 2; PST `!BDN` + format code; DWG `AC10` + digits + zero pad; Kdbx/Lnk/Blend/Djvu/Chm/Cab/Ar/Gz/Bz2/Zstd all carry secondary field checks.
**End detection (`measure`, `formats.rs:544-595`).** Per-kind structural walks:
- JPEG: marker walk to SOS, then the first `FF D9` after it (EXIF thumbnails skipped by length; progressive later scans precede EOI) (`formats.rs:597-626`).
- PNG: chunk walk to `IEND` (`628-641`); GIF: block walk (`643-677`); BMP: header size else dimension math (`688-701`).
- TIFF-family: walks every IFD/SubIFD/EXIF/GPS (≤ 64 IFDs, ≤ 1000 entries each) taking the furthest strip/tile/thumbnail byte; types raws by header marker (CR2/ORF/RW2), DNG tag 50706, or camera make (NIKON→nef, SONY→arw) (`703-805`); RW2 stays header-only (raw data has no stored length — `ponytail` note, `731-733`).
- PDF: the **last** `%%EOF` not followed by an incremental update (`894-928`).
- ZIP: the EOCD whose central directory ends exactly where the EOCD starts (`cd_off + cd_size == eocd_pos`) — rejects the EOCD of a zip stored inside; ZIP64 locators; central directory read to type docx/xlsx/pptx/vsdx/3mf/apk/xps/odt…/epub/jar by member names or the stored `mimetype` entry (`1076-1148`).
- MP4: top-level box walk requiring `moov`+`mdat` (`meta` for HEIC/AVIF); size-0 box = runs to EOF = unknown end (`1150-1210`).
- OLE: size from the highest non-free FAT sector (+DIFAT chains); type from root-storage stream names (WordDocument/Workbook/PowerPoint Document/`__substg1.0_`→msg) (`935-1000`).
- RIFF/AVIX chaining; MKV EBML segment size (unknown-size segments fall back); FLV tag-size self-consistency; ASF File-Properties size + wmv/wma by video stream GUID; MPEG pack/PES walk to end code; MP3 frame-by-frame with consistent version/layer/rate bits + ID3v1 trailer; Ogg page CRC (own non-reflected CRC-32, `1441-1450`) + end-of-stream on all serials; TS sync run; MIDI track chunks; SQLite page count trusted only when `version-valid-for == change counter`; 7z header CRC; RAR4/5 block walks; xz stream-footer CRC; zstd frame/block walk; tar two zero blocks; ar members; PE furthest section or Authenticode signature; ELF furthest section/segment (an end past the section-header table means the table read is another file's data — "better an unknown end than a giant bogus one", `1726-1732`); PST `ibFileEof`; LNK extra-data blocks to zero-size terminator; regf `hbin` chunk run; evtx `ElfChnk` chunk run; font table-directory max; woff declared total; blend `ENDB`.
- **No recoverable end** (bounded guess): `Gz | Bz2 | Flac | Amr | Xcf | Kdbx | Dwg` (`formats.rs:590-592`).
**Header/footer + bounded guessing.** Per-kind `max_size()` (1 MiB lnk → 64 GiB video/pst) rejects false header matches (`formats.rs:294-310`); `unknown_end_size()` (1–256 MiB) caps headerless runs (`314-324`); `search_limit()` up to 1 GiB for footer search (`327-332`). With no end found, a file runs to **the next recognizable header of any type** or the cap (`unknown_end`, `carve/mod.rs:159-169`).
**Fragmentation handling.** None — "Carving doesn't reassemble fragmented files" (`README.md:193`; no such code). Overlap suppression: after a file claims `[start, ceil((start+size)/sector)*sector)`, scanning resumes past it — "its insides (thumbnails, embedded zips) aren't separate files" (`carve/mod.rs:88-103`). **Dedup**: none beyond that claim-skip (two headers at different offsets both produce files).
**Output.** `--out/<type_id>/f{:07}.{type_id}` where the number is the start sector (`carve/mod.rs:138-139`); `complete=false` when the end wasn't found, the file runs off the source end, or any byte overlapped an unreadable range (`carve/mod.rs:127-153`). `--types` validated with a known-list error (`carve/mod.rs:48-56`); `--start/--end` byte range (GUI derives it from the selected partition, `gui/src/lib/recoverlogic.ts:16-20`).
**Scan loop.** 16 MiB chunks + `HEADER_LEN = 1024` over-read; `identify()` at each sector boundary; candidates in unreadable sectors skipped (`carve/mod.rs:18-20,66-109`). `Probe` gives parsers windowed bounded reads (1 MiB window) with `get/get_upto/find` (`probe.rs`).
**UX.** Carve tab: checkbox grid of all 94 types with Select all/none, partition-limited range, "Save to" chooser, results table (type badge, saved-as name, size, byte offset, Complete/Incomplete) (`gui/src/screens/recover/CarveTab.tsx:91-166`).

### 2.9 Direct hardware access
**Sources.** `crates/sf-core/src/device/{mod,windows,linux,file_backend}.rs`; routing `sf-cli/src/lib.rs:220-273`.
**Behavior / algorithm.**
- Path routing: source starting `\\.\` or `/dev/` = device mode; anything else = image file (`is_raw_device_path`, `lib.rs:222-224`). `FileBlockDevice` takes an explicit sector size (512 default — "a plain file has no real alignment requirement") (`file_backend.rs:18-30`).
- Windows open (`device/windows.rs:53-100`): `CreateFileW(\\.\PhysicalDriveN, FILE_GENERIC_READ, FILE_SHARE_READ|FILE_SHARE_WRITE, OPEN_EXISTING, FILE_FLAG_NO_BUFFERING)` — "bypasses the OS cache so a failing drive's real sector health is what the imager actually sees, matching what `ddrescue -d` does" (`windows.rs:1-4`). Size via `IOCTL_DISK_GET_LENGTH_INFO`; sector via `IOCTL_DISK_GET_DRIVE_GEOMETRY_EX` (fallback 512).
- `Access::{Os, Scsi, Ata}` (`device/mod.rs:31-43`): SCSI READ(16) (CDB opcode `0x88`, LBA be64 at CDB[2..10]) and ATA READ DMA EXT (48-bit, `ATA_FLAGS_DRDY_REQUIRED|DATA_IN|48BIT_COMMAND|USE_DMA`) via `IOCTL_SCSI/ATA_PASS_THROUGH_DIRECT`, each with its own `TimeOutValue` (`--timeout`, default 10 s, range 1..=3600) "so a bad sector costs seconds rather than the disk driver's minutes" (`windows.rs:6-10,157-212`); reads split into ≤ `PASS_THROUGH_MAX = 64 KiB` commands for adapter limits (`windows.rs:37-39,244-255`); pass-through needs `GENERIC_WRITE` on the handle ("Windows only allows pass-through on a handle opened for writing, but the only commands ever built here are fixed read opcodes", `windows.rs:8-10,67`). Pass-through is probed with one sector at open so failure is explained up front with per-mode hints (NVMe/USB caveats) (`windows.rs:88-98`). Sense key/ASC/ASCQ parsed from fixed or descriptor sense (`windows.rs:228-233`).
- Linux (`device/linux.rs`): `open(O_RDONLY | O_DIRECT)` + `pread`; `BLKSSZGET = 0x1268`, `BLKGETSIZE64 = 0x8008_1272` passed as raw numbers for glibc/musl ioctl-type compatibility (`linux.rs:16-19,35-50`); module header admits "Not yet exercised on real Linux hardware" (`linux.rs:5-8`) — CI covers loop devices only. SCSI/ATA pass-through explicitly unavailable on Linux ("use --access os", `sf-cli/src/lib.rs:262-266`).
- Error propagation: short reads over a direct handle are `UnexpectedEof` errors, matching the trait contract that a read "either succeeds in full or fails in full" (`block_device.rs:23-29`; `windows.rs:273-278`; `linux.rs:85-90`).
- Alignment: `AlignedBuf` = manually allocated, power-of-two-aligned, zeroed heap buffer; direct I/O requires the buffer *address* aligned, "a plain Vec<u8> gives no such guarantee" (`aligned_buf.rs:1-6,20-32`).

### 2.10 Drive listing, inspector UX, same-drive guard
**Sources.** `crates/sf-core/src/drives/{mod,windows,linux}.rs`; `gui/src/components/DriveInspector.tsx`.
**Behavior / algorithm.**
- `DriveInfo {path, model, serial, size, sector_size, bus ∈ {sata,nvme,usb,scsi,sd,virtual,other}, removable, system}` (`drives/mod.rs:13-24`).
- Windows listing needs **no elevation**: `\\.\PhysicalDrive0..63` opened with **zero desired access** (enough for property/geometry IOCTLs) (`drives/windows.rs:1-3,25,43-49,73-115`); `IOCTL_STORAGE_QUERY_PROPERTY` descriptor parsed: vendor+product merged into model (unless vendor is "ATA"); NVMe serials' trailing `.` trimmed; bus from bus-type code (0x01/0x0A scsi, 0x02/0x03/0x0B sata, 0x07 usb, 0x0C/0x0D sd, 0x0E..0x10 virtual, 0x11 nvme); removable bit (`windows.rs:136-168`).
- Geometry from `GEOMETRY_EX`, falling back to legacy `DISK_GEOMETRY` because "GEOMETRY_EX asks the drive itself, which a failing drive may not answer (error 1117). The legacy geometry is cached by Windows; its C×H×S product is a cylinder short at most" (`windows.rs:90-101,117-125`).
- System drive from `%SystemDrive%` → volume → disk extents (`windows.rs:74-81`).
- Linux listing: `/sys/block` minus `loop/ram/zram/dm-/md/sr/fd/nbd` name prefixes; size = sysfs `size` × 512 ("always in 512-byte units"); serial from `device/serial` → `serial` → SCSI VPD page 0x80; bus from the canonicalized sysfs path; `removable`; system = backing of `/` (`drives/linux.rs:14-79`).
- `is_elevated`: Windows token elevation (`GetTokenInformation/TokenElevation`); Linux euid==0 or any drive readable by this user (disk group) (`drives/windows.rs:170-188`, `drives/linux.rs:81-90`).
- **Same-drive guard**: `backing_of_source` — Windows `\\.\PhysicalDriveN` direct, `\\.\E:`/volumes via `IOCTL_VOLUME_GET_VOLUME_DISK_EXTENTS` (`windows.rs:190-221`); Linux canonicalize + `base_disks` following partitions up to their disk and dm/md `slaves/` down to real disks (depth ≤ 16) (`linux.rs:124-155`), with a `/proc/self/mountinfo` longest-mount-point fallback (with `\ooo` octal unescape) for anonymous btrfs device numbers (`linux.rs:157-187`). `backing_of_output` walks to the nearest *existing* ancestor and canonicalizes (`drives/mod.rs:107-116`); Windows `GetVolumePathNameW` → `GetDriveTypeW` (REMOTE/RAMDISK → NotLocal) → volume GUID → extents (`windows.rs:223-246`).
- Refusal messages are deliberate plain English: "refusing to start: {what} {} is on the source drive ({d}). Writing to a failing drive is how data gets destroyed. Choose a location on a different drive." — and an equal refusal when the backing disk **can't** be determined ("guessing wrong here means writing onto the failing drive") (`drives/mod.rs:80-104`). Known blind spot: Windows Storage Spaces exposes the virtual disk, not members (`README.md:196-197`).
- **Drive inspector UX** (`gui/src/components/DriveInspector.tsx`): slide-in panel per drive; System-drive / Removable badges (`166`); red notice when the startup survey hit a read error — "This drive returned a read error… Every read can make it worse, so if anything on it matters, image it before doing anything else" (`176-186`); partition map drawn to scale + clickable table (filesystem, label, start LBA, size, confidence badge) (`197-227`); **Details** table: Size (formatted + exact bytes), Connection (bus label), Sector size, Serial number ("not reported" when absent), Path, Table kind, and SHA-256 when previously verified (`142-155,252-270`); actions: **Image this drive** (highlighted primary when the drive has read errors, `79-91`), Quick rescan ("Read the partition table again (a few KB)"), Deep scan, Recover files, Verify (SHA-256), Partitions screen (`93-140`). Home screen tiles show every drive with survey results/error flags (`HomeScreen.tsx:25`).
- Elevation UX: Windows — the unelevated exe relaunches itself via `runas` (UAC), passing `--elevated --source/--dest/--map/--screen` restore args (proper `CommandLineToArgvW` quoting, `gui/src-tauri/src/lib.rs:376-422`), separating the WebView2 profile dir for the elevated copy (`684-689`), the elevated copy watching the parent PID to exit with it (`560-573`); an in-app restart command refuses while a job runs (`525-531`); user-declined prompts get specific messages (1223 = cancelled) (`613-617`). ## 3. The named feature in full detail — recovered files WITH original directory structure
**Verdict: FOUND AND FULLY IMPLEMENTED.** It is not an option/toggle: directory reconstruction is the *inherent* behavior of `sf-cli extract` — "Copy files out of a partition by id (from `files`)" with output "recreating the selected files' folder structure in" `--out` (`sf-cli/src/lib.rs:147-164`; `crates/sf-core/src/ntfs/extract.rs:1-4` "recreating folders under the output directory"). It is exercised as a **post-scan step** (after `scan` + `files`), and the same code path serves NTFS, FAT/exFAT and ext through the shared `Volume`/`Index` abstraction.

**UX flow (exact names and places).**
1. Recover screen → "Browse files" tab → "Partition to list" panel → "List files" button (`gui/src/screens/recover/FilesTab.tsx:30-65`). CLI: `sf-cli files --source S --partition-lba N` (`README.md:162`).
2. Optional deleted-only **pre-filter**: checkbox "**Only list deleted files (quicker on very large volumes)**" (`FilesTab.tsx:54-56`) → `--deleted-only` flag → CLI skips in-use entries (`recover.rs:241-243`: `if deleted_only && e.in_use { continue; }`). Deleted-only affects *listing* only, never extraction behavior. The GUI starts a deleted-only run in flat search mode because "A deleted-only run has no live folders to browse through" (`store/actions.ts:239-240`). Post-listing, the browser's "Deleted only" checkbox is a client-side filter over the already-listed store (`FileBrowser.tsx:155-157`; `filestore.ts:165-178`).
3. The browser shows real names and folders with breadcrumbs, an "Orphaned files (N)" pseudo-folder, per-row Deleted badge and Fully/Partly/Not-recoverable badge (`FileBrowser.tsx:104-131,217-221`).
4. User ticks files and/or folders (hint: "Selecting a folder extracts everything inside it.", `FilesTab.tsx:149`), sets "Extract to" (folder picker; placeholder "A folder on a different drive from the one you are rescuing"), presses "**Extract selected**" (`FilesTab.tsx:112-153`). Extraction is hard-bound to the source/partition that produced the listing (`listedFor`, `store/recover.ts:38-39`; `actions.ts:255-271`).
5. Progress: "Reading the file table before extracting: N of M" (extract re-reads the full index to resolve folders/paths — `docs/cli-contract.md:249-251`), then `extract_progress` (files_done/files_total, bytes_done/bytes_total), one `extracted` event per item, `done{extracted, failed}` (`recover.rs:291-345`; `gui/src/store/events.ts:128-161`). GUI panel: progress bar + rows (path, size, Complete/Incomplete/Failed badge, note with tooltip) (`ExtractPanel.tsx`).
6. Selections > 200 ids go through a temp `--ids-file` (Windows ~32 k command-line limit), deleted on failure (`gui/src-tauri/src/lib.rs:242-279`).

**Engine algorithm** (`crates/sf-core/src/ntfs/extract.rs`):
- `extract(vol, index, ids, out, on_item, on_progress)` (`90-126`): `create_dir_all(out)`; `out` canonicalized once; `plan()`; per-id `Writer::extract_one`; ok/failed counters; `bytes_total` summed from index sizes.
- `plan(index, ids)` (`130-150`): DFS from each selected id over `index.children()` (parents before children), each id exactly once (`seen` HashSet); the root id itself is never emitted; **children are pulled in only when `index.is_listed()`** — "Filesystem metadata (NTFS $MFT, $Extend…) is never pulled in implicitly" (`145`); unknown ids stay in the plan so they surface as reported failures (`129`).
- **Parent references → directories.** For a directory id, `Writer::dir_for` (`216-238`): root (id 5) maps to `out` itself; otherwise the parent comes from `index.ancestry(id)` — `Rooted(chain)` recurses into `chain[len-2]` (the record's actual parent, validity decided by the sequence-number rules of §2.5: `pseq` exact, or `pseq+1` for a deleted parent, parent must be a dir); the directory's sanitized name is appended; `Writer.dirs` caches id→path so shared parents are created once.
- **Orphans.** `Ancestry::Orphaned(chain)` → base is `out/_orphaned` (`ORPHANS = "_orphaned"`, `extract.rs:14,209-213`). An orphan *root* additionally gets its id appended — "orphan roots also get their id, so two orphaned 'Documents' folders don't merge" (`top_name`, `199-207`) — while its descendants keep their real relative structure beneath it. In the listing UI, orphans (`path: null`) are grouped in the "Orphaned files (N)" pseudo-folder keyed `":orphans:"`, which "real folder keys always start with '/', so this cannot collide" (`gui/src/lib/filestore.ts:3-4`).
- **Output path/naming.** Target = parent dir + `safe_component(name)`; reported `path` is `out`-relative, `/`-separated (`rel`, `254-257`).
- **Collision handling** (`extract_one`, `161-197`): if the target **exists on disk** or was **written earlier in this run** (`Writer.written` HashSet), retry as `name (id N).ext` — `with_id_suffix` inserts ` (id N)` before the extension (`sanitize.rs:66-71`) — e.g. a deleted and a live `report.docx` in one folder both survive. If that also collides or the target is a directory, the item **fails** with "an output file with the same name already exists": **nothing pre-existing is ever overwritten** (verified by test: a user's pre-existing `Docs/a.txt` keeps its bytes and the recovered file becomes `Docs/a (id 17).txt`, `ntfs/tests.rs:425-435`). Directory-name collisions with an existing *file* fall back to the id-suffixed dir name (`dir_for`, `232-234`).
- **Path-traversal safety.** Every component passes `safe_component` (`sanitize.rs:11-36`): `\ / : * ? " < > |` and control chars → `_`; `.`/`..` neutralized; **trailing dots/spaces replaced with `_`** (Windows silently strips them, which would make different names collide); empty → `_`; reserved Windows names (CON, PRN, AUX, NUL, CONIN$/CONOUT$, COM1-9/¹²³, LPT1-9) prefixed `_`; UTF-16-truncated to 240 units preserving a short extension. Identical rules on every OS "so a recovery made on Linux can still be copied onto a Windows machine" (`sanitize.rs:1-5`). Additionally `make_dir` canonicalizes every created directory and refuses one that resolves outside `out` — "leads outside the output folder" — guarding against pre-existing junctions/symlinks inside the output (`extract.rs:242-252`).

## F-18/F-20 — Signature registry + dispatch (SectorForge)

Naming correction vs the matrix row: SectorForge has NO literal
offset-keyed first-byte-bucket index. Its "index" is a two-level
conceptual model: 51 `Kind` enum variants (parse kernels,
formats.rs:181-233) map upward to 94 user-facing type IDs (the TYPES
table, formats.rs:83-178) via one-to-many mapping (e.g. OLE →
doc/xls/ppt/msg/ole; ZIP → 14 ids). Dispatch is a straight-line
first-match-wins cascade ordered by signature specificity
(formats.rs:345-541).

**Type declaration layers**: (1) Kind enum — the parse kernel; (2)
TypeInfo {id, description} — the CLI-visible registry; (3) kind→ids
mapping; (4) per-kind parameter methods.

**Header validation grammar** (`identify(b)`, formats.rs:345): requires
≥16 bytes, zero-pads short buffers to HEADER_LEN=1024. Every check is
"magic + structural fields", never a bare magic: JPEG needs FFD8FF plus
`b[3] >= 0xC0 && != 0xFF`; ZIP needs PK\x03\x04 plus version-major < 100
and minor == 0; MP4 needs `ftyp` at offset 4 plus box size in 16..=512,
multiple of 4, ASCII-graphic brand; OLE needs the D0CF11E0 magic plus
byte-order 0xFFFE and sector/mini-sector shift pairs (3,9) or (4,12);
tar needs `ustar` at 257 plus a verified header checksum; XZ verifies a
CRC32 of bytes 6..8.

**Scan loop** (mod.rs:58-111): 16 MiB chunks with a 1024-byte header
window overlap; candidates accepted only at sector boundaries and only if
the first sector is not in an unreadable range. Once a file is carved,
scanning resumes after its claimed end — embedded thumbnails/zips are
not double-counted. Probe = 1 MiB sliding-window bounded reader relative
to file start.

**Thresholds**: max_size per kind (lnk 1 MiB; ico/mid/font/woff/amr
64 MiB; jpg/gif 128 MiB; png/kdbx 256 MiB; a 1 GiB tier; pdf/sqlite/
ole/tif/aiff/cab/regf/blend 4 GiB; archives and psd 16 GiB; media and
pst 64 GiB); unknown_end_size (1 MiB lnk / 16 MiB images+small+mp3 /
256 MiB video / 64 MiB default); search_limit (1 GiB for pdf/zip/ps/xz
footer searches, else max_size); SCAN_CHUNK 16 MiB, HEADER_LEN 1024,
COPY_CHUNK 4 MiB.

**UX**: `--list-types` prints id+description; `--types` filters; output
files in per-type subdirs named by 512-byte offset (`f{:07}.{type}`).

## F-22/F-23 — End detectors + outcome honesty (SectorForge)

**PDF** (formats.rs:894-928): repeatedly find `%%EOF`; the EOL after it
is consumed as part of the file; if the following ≤64 bytes
`looks_like_pdf_update` (starts with `xref` or `%`, or matches `digits
digits obj`) keep searching after that EOF — the incremental-update
rule. Otherwise the file ends there.

**MP4** (formats.rs:1150-1210): walk 32-bit-size ISO boxes whose type is
a top-level set (moov, mdat, free, skip, wide, uuid, pdin, meta, moof,
mfra, styp, sidx, ssix, prft, emsg, pnot, junk). Complete only if BOTH
the index box and `mdat` were seen; the index box is `moov` for video
but `meta` for HEIC/AVIF. Size==1 means read a 64-bit largesize; size<8
or overflow ⇒ no end; size 0 (to-EOF) treated as unknown.

**OLE** (formats.rs:930-1000): reconstruct the full FAT (header 109
entries + DIFAT chain); size = `(last_non_FREE_fat_index + 2) ×
sector_size` (FREE = 0xFFFFFFFF). Type from root-storage stream names
(read ≤64 directory sectors, walk the root's child sibling tree):
`__substg1.0_*`⇒msg, `WordDocument`⇒doc, `Workbook`/`Book`⇒xls,
`PowerPoint Document`⇒ppt, else ole.

**ZIP** (formats.rs:1076-1148): scan for `PK\x05\x06` from offset 4;
accept only if `cd_off + cd_size == eocd_position` (rejects EOCDs of
archives nested inside the archive). Handles Zip64 (0xFFFFFFFF sentinels
resolved via the `PK\x06\x07` locator → `PK\x06\x06` record). Final size
= eocd_pos + 22 + comment_len; sub-type from central-directory entry
names (`word/document.xml`⇒docx, ..., `mimetype` entry content for
ODF/EPUB).

**Honesty rules** (mod.rs:115-169):
- measured length > kind.max_size ⇒ DISCARDED as a false match (falls
  through to the unknown-end path);
- found but > available (runs off source end) ⇒ write available bytes,
  `complete = false`;
- no end found ⇒ write `unknown_end_size()` bounded by NEXT-HEADER
  termination (scan sector-by-sector, stop at the first offset where any
  type's identify() matches), `complete = false`;
- any short/failed read during the copy ⇒ `complete = false`; final
  `complete &= !reader.is_unreadable(abs, abs+size)` (unreadable-range
  overlap check);
- user-visible: ` (incomplete)` suffix per file; JSON events carry
  `"complete": bool` per file.

## F-28 — FAT32 orphan-directory subtree harvesting (Halim)

Reference: `src/.../Fat32Scanner.cs` (C#).

**The orphan invariant** (WalkDirectory :131-139): a LIVE-LOOKING
directory entry whose first cluster is FREE in the FAT is an orphaned
deleted tree — diverted to the deleted-directory walk. A 0xE5-deleted
directory with a free cluster goes the same way (:173-178).

**Deleted-directory walk** (:191-208): walks CONTIGUOUS clusters (the
FAT chain was zeroed on delete) up to 256 clusters, guarded by a shared
visited set. STRICT PARSE: the first cluster must begin with `.` (the
self-entry of a real directory) or an 0xE5-deleted entry (:202); any
subsequent cluster that is NOT free means it was reused by live data ⇒
stop (:203).

**Harvest** (:211-259): 32-byte entries; 0x00 terminator ends the
directory; LFN entries (attr 0x0F) buffered and joined; EVERY child is
recoverable regardless of its own deleted flag — Windows never rewrites
child entries when deleting a tree (:186-189). Child dirs recurse only
if their cluster is free (:236-237). Files get one contiguous extent
from the first cluster.

**Constants**: depth ≤ 64 (:89,:195); contiguous orphan walk ≤ 256
clusters (:196); chain guard 1,000,000 (:95); FAT mask 0x0FFFFFFF (:79);
cluster validity `>= 2 && < TotalClusters + 2`.

**Edge cases**: shared visited set across walkers (cycles); cluster
reuse stops the walk; LFN sequence bytes destroyed by 0xE5 handled by
reversing disk order (:286-293); deleted short names get `_` for the
destroyed first byte (:295-303); overwrite risk quantified as
OverwrittenFraction = fraction of the assumed-extent clusters now
allocated to a live owner (:261-272).

**UX**: per-file HealthNotes rendered as a bulleted list in the details
pane + tooltip: "FAT32: cluster chain lost on delete; contiguous layout
assumed", "recovered from deleted directory".

## F-29 — exFAT allocation-bitmap authority (Halim)

Reference: `src/.../ExFatScanner.cs`.

**Authority rule** (:102-104, :131-141): for deleted sets the FAT is
STALE; the allocation bitmap is authoritative for cluster state.
`IsClusterAllocated`: bitmap first (bit N = cluster N+2), FAT only as
fallback.

**Entry sets** (:143-219): 0x85/0x05 (file; 0x05 = deleted with in-use
bit cleared), 0xC0/0x40 (stream extension: NoFatChain flag bit 0x02,
first cluster, 64-bit data length), 0xC1/0x41 (name chunks, 15 UTF-16
chars each). `treatAllAsDeleted` propagates the orphan-subtree rule
(:96-100).

**Emit** (:221-271): directories recurse when live, or when deleted and
their cluster is free per the BITMAP (:230-240); the walk is capped at
the directory's declared cluster count and assumed contiguous
(`chainValid: false`).

**Constants**: depth ≤ 64 (:147); guard 1,000,000 (:150); bitmap length
sanity ≤ 128 MiB (:117); plausible first-type byte whitelist for
directory clusters (:74-76); FAT next-cluster window `2 ..< 0xFFFFFFF7`
(:211).

**UX**: NoFatChain set ⇒ note "exFAT: NoFatChain set — file was stored
contiguously (exact layout known)" (:259); chain lost ⇒ contiguous
assumption note (:160,:254).

**Load-bearing ideas for re-implementation**: (1) the FAT-free-cluster
orphan test; (2) the strict first-cluster `.`/0xE5 plausibility gate;
(3) the children-never-rewritten recovery rule; (4) bitmap-over-FAT
authority on exFAT; (5) bounded contiguous walks (64 depth / 256
clusters FAT32; declared-length cap exFAT).

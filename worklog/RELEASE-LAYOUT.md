## 1. The release pipeline (`.github/workflows/release.yml`)

- **Trigger**: push of a tag matching `v*` (release.yml:21-24). A tag build is never
  cancelled (concurrency `release-${{ github.ref }}`, cancel-in-progress false,
  release.yml:26-28). Permissions: `contents: write` for the release upload
  (release.yml:31-32).
- **Version derivation / gate**: the root `VERSION` file is the ONLY version source;
  the workflow refuses any tag that does not equal `v<VERSION>` (release.yml:41-53).
  `build.ps1` additionally fails if `ui/package.json`, `ui/src-tauri/Cargo.toml` or
  `ui/src-tauri/tauri.conf.json` drift from `VERSION` (build.ps1:37-46). Tag
  naming: `v0.9.6` for VERSION `0.9.6` — exactly; no `-rc` suffix in final tags
  (RC discipline `v<version>-rc1` exists for pre-public checks, docs/RELEASE.md:81-86).
- **Runner**: `windows-2022`, timeout 90 min (release.yml:35-37). Toolchain steps:
  pnpm 12.15.0 (release.yml:58-60), Node 24 (release.yml:62-66), Rust stable
  (release.yml:68-70). The vcpkg binary cache is a RUNNER_TEMP directory
  (release.yml:44-46, 75-77).
- **Build**: `./build.ps1 -Target all` (release.yml:79) — contracts → engine →
  ui+tauri → NSIS installer → portable zip → SHA256SUMS (build.ps1:290-297;
  docs/BUILD.md:8-9,29-49).
- **Verification step** (release.yml:82-103): asserts the three artifacts exist —
  `build\out\RecoveryWizard-$version-setup.exe`, `build\out\RecoveryWizard-$version-
  portable.zip`, `build\out\SHA256SUMS` (release.yml:86-90) — and dev-signs are
  verified on the setup.exe AND on `build\out\stage-$version\engine\cr_ui.dll`
  via `installer\devsign.ps1 -Action verify` (release.yml:96-101).
- **Upload**: `softprops/action-gh-release@3bb12739...` (# v2) with
  `body_path: release-notes.md`, `fail_on_unmatched_files: true`, files:
  `build/out/RecoveryWizard-*-setup.exe`, `build/out/RecoveryWizard-*-portable.zip`,
  `build/out/SHA256SUMS` (release.yml:294-302). Release notes are composed inline
  with the SHA256SUMS pasted in (release.yml:105-292).
- **Evidence artifact** (not a release asset): `release-build-evidence` via
  actions/upload-artifact v4, 14-day retention, **excluding** `build/out/stage-*`
  and `build/out/devsign.*` so the ephemeral signing material never rides an
  artifact (release.yml:304-317).
- **Measured precedent**: v0.9.5 release run 44365218107 GREEN end to end, 1224 s
  = 20.4 min; assets setup.exe 2,877,168 B, portable.zip 4,039,372 B + SHA256SUMS
  (worklog.md, "v0.9.5 release" entry). v0.9.0 run 42274682840 SUCCESS ~23 min

## 2. Build staging — what `build.ps1` produces and where

- `$OutDir = build\out`, `$StageDir = build\out\stage-<version>` (build.ps1:30-32).
- **Engine lane** (build.ps1:56-145): CMake win-x64-Release + ctest; PE Win7 gates on
  `rrecov.exe` + `cr_ui.dll` (build.ps1:88-97); then the **engine kit is staged** at
  `build\out\stage-<v>\engine\` containing: `cr_ui.dll`, `cr_ui.lib`, `rrecov.exe`,
  the vcpkg runtime DLLs deployed beside cr_ui.dll by `cr_deploy_vcpkg_binaries`
  (gtest/gmock excluded — build.ps1:112-120; engine/CMakeLists.txt:156-167), and
  `userdata-defaults.json` (the 111-entry default user-sign set; build.ps1:133).
  devsign then embed-signs the STAGED `cr_ui.dll` + `rrecov.exe`
  (build.ps1:140-144).
- **Engine CMake has NO install() rules** — there is no cmake-install of `cr_ui.dll`,
  `rrecov.exe` or headers; the shipped kit is assembled by `build.ps1` Copy-Item
  from the build tree (`engine/build/win-x64-<cfg>/src/{app,ui}/Release/`,
  build.ps1:88-91,114-115). Targets: `add_executable(rrecov rrecov.cpp)`
  (engine/src/app/CMakeLists.txt:1), `add_library(cr_ui SHARED cr_ui.cpp)`
  (engine/src/ui/CMakeLists.txt:11).
- **UI lane** (build.ps1:147-208): stages the kit into
  `ui\src-tauri\target\{release,debug}\` (build.ps1:168-176) — so the BUILD-TREE exe
  carries the same flat kit layout as the installed one — builds with
  `pnpm tauri build` (NSIS-only bundle; tauri.conf.json bundle targets `['nsis']`),
  then the **D1 gate** byte-scans the built exe for `requireAdministrator`
  (build.ps1:188-203). App exe name = Cargo package name `recovery-wizard-ui`
  (ui/src-tauri/Cargo.toml; recoverywizard.nsi:150 — no mainBinaryName override).
- **Installer lane** (build.ps1:222-260): picks the version-locked Tauri NSIS bundle
  (`*<v>*-setup.exe`, I-STALE-01 hard stop on mismatch, build.ps1:229-236), runs
  `makensis` with `/DPRODUCT_VERSION=<v> /DAPP_BUNDLE=<path> /DENGINE_KIT=<stage\
  engine> /DOUT_DIR=<build\out> /DPATHSEP=\` (build.ps1:246-248), then devsigns the
  setup.exe (build.ps1:255-258).
- **Portable lane** (build.ps1:262-271) + checksums (273-281).

- **Loader truth**: the Rust bridge STATICALLY imports cr_ui.dll, so the kit DLLs
  ride BESIDE the exe at `$INSTDIR` — an `engine\` subfolder would 0xc0000135 at app
  start (nsi:301-311; docs/BUILD.md:61-72). `cr_ui.lib` is deliberately NOT installed
  (NSIS `File /x cr_ui.lib`, nsi:251) — though it IS present in the stage dir and in
  the portable zip (portable.ps1:47).
- **Registry (HKLM, SetRegView 64)**:
  - `HKLM\Software\HeicFast\Recovery Wizard` values `InstallDir`, `Version`,
    `InstallMode=AllUsers` with read-backs (nsi:149,383-394).
  - `HKLM\Software\Microsoft\Windows\CurrentVersion\Uninstall\Recovery Wizard`
    (key name = product name): DisplayName "HeicFast Recovery Wizard",
    DisplayVersion, Publisher "HeicFast", InstallLocation, UninstallString
    `"$INSTDIR\HeicFastUninstall.exe"`, QuietUninstallString `...\HeicFastUninstall.exe" /S`,
    NoModify=1, NoRepair=1 (nsi:148,401-408). Inner Tauri uninstall keys pointing
    into $INSTDIR are swept and replaced by this single entry (nsi:396-410).
  - Seeded inner-install key `HKLM\Software\heicfast\Recovery Wizard` (default
    value = $INSTDIR) steers the inner setup's install dir (nsi:267-276) and is
    removed again at uninstall (nsi:643-654).
- **Services / drivers / certificates: NONE** — user-mode only; no `System32\drivers`
  write, no SCM service, no certificate-store import anywhere (nsi:20-22;
  docs/INSTALLER.md:49-51; asserted by installer-matrix.ps1:245-260).
- **Shortcuts**: the OUTER script creates none; the inner Tauri template owns the
  Start Menu set (probed + asserted to target $INSTDIR — installer-matrix.ps1:299-328).
- **Expected module set asserted by validation** (exact list):
  `recovery-wizard-ui.exe`, `uninstall.exe`, `HeicFastUninstall.exe`, `cr_ui.dll`,
  `rrecov.exe`, `userdata-defaults.json` + ≥1 runtime DLL class, flat only
  (installer-matrix.ps1:262-296) — ~8 files ("our installed set ... 8 flat files +
  ProgramData + registry", docs/INSTALL-FOOTPRINT-DELTA.md:111-112).

## 5. Silent / headless install — commands, elevation, exit codes

- **Silent install**: `setup.exe /S` (NSIS standard; documented docs/INSTALLER.md:38;
  executed by install-probe.ps1:70 and installer-matrix.ps1:132 as
  `/S /allusers` — the outer wrapper itself is all-users-only, the extra flag is
  inert). Measured: v0.9.5 shipped setup.exe on a fresh runner — **exit 0 in 5.6 s**
  (worklog.md, forensic run 44369227822); 0.6-era t15 install row: exit 0, 9384 ms
  (t15-runtime-matrix.md:8).
- **Elevation**: installer carries `RequestExecutionLevel admin` (nsi:174) — ONE
  UAC prompt at launch; on GitHub Windows runners the shell is already elevated
  (forensic-repro runs entirely unelevated-prompt-free). The inner Tauri bundle is
  driven `app-setup.exe /S /allusers /D=$INSTDIR` via ExecWait (nsi:278) — ExecWait,
  NOT nsExec, because a quoted /D= is ignored by NSIS parsers (nsi:206-216).
- **Exit codes**: 0 = success. Abort paths exit **2** (NSIS Abort; the Win10 gate
  comment: "the Abort below still refuses the install with exit code 2, which is
  the truthful outcome", nsi:528-533). PRECEDENT: the v0.9.4 shipped installer
  aborted with **exit 2 on every machine except the build machine** (the G-4
  pre-flight probed the compile-time ENGINE_KIT path at runtime — CI-FAILURES.md §11
  :159); FIXED in 5798cf39 by verifying the extracted `$PLUGINSDIR\engine-kit` payload
  instead (nsi:228-265) — v0.9.5 installs clean. Silent aborts leave the reason in
  `%TEMP%\HeicFastRecoveryWizard-install-abort.txt` (nsi:83-96) — read it before
  diagnosing any nonzero exit (installer-matrix.ps1:166-171).
- **Message boxes never block silent runs** — every box carries a safe `/SD` default
  (installer/README.md:73-82).
- **Silent uninstall**: `HeicFastUninstall.exe /S` (registry QuietUninstallString,
  nsi:406). For a synchronous run (the uninstaller otherwise copies itself to
  %TEMP% and returns immediately): `Start-Process $un '/S',"_?=$instDir" -Wait`
  (forensic-repro.yml:248-252). Exit 0 expected; the ONE documented `_?=` survivor
  is the uninstaller's own exe, cleaned by the caller (forensic-repro.yml:256-284;
  RELEASE-RUN.md, forensic #29 step 10). Pre-sweep `recovery-wizard-ui` and its
  `msedgewebview2.exe` children first or locked files silently survive while the
  exit code stays 0 (forensic-repro.yml:237-245; RELEASE-RUN.md run 25).

## 6. Fetching the latest release assets from GitHub

Repo: `heicfast/final-prod` (release URLs throughout RELEASE-RUN.md; the workflow's
own download lane forensic-repro.yml:79-95 uses plain unauthenticated `curl.exe`).

- **API**: `GET https://api.github.com/repos/heicfast/final-prod/releases/latest` →
  `tag_name` (e.g. `"v0.9.6"`) and `assets[]` with `name` + `browser_download_url`.
  Asset names EMBED the version, so resolve the tag first:
  `RecoveryWizard-<version>-setup.exe`, `RecoveryWizard-<version>-portable.zip`,
  `SHA256SUMS` where `<version>` = `tag_name` minus the leading `v`.
- **Direct (the in-repo proven pattern)**: for a known tag
  `$base = "https://github.com/heicfast/final-prod/releases/download/$tag"` then
  `curl.exe -sSL -o setup.exe "$base/RecoveryWizard-$ver-setup.exe"` and the same
  for `SHA256SUMS` (forensic-repro.yml:84-89).
- **Checksum verification** (copy from forensic-repro.yml:90-95): parse SHA256SUMS
  with regex `([0-9a-fA-F]{64})\s+\*?RecoveryWizard-<ver>-setup\.exe`, compare with
  `Get-FileHash -Algorithm SHA256`; mismatch = hard fail. SHA256SUMS format is
  `<hash>  <name>` per file (build.ps1:278-279).
- Legacy-releases fallback: `.../releases/tags/<tag>` or the `releases/latest/download/
  <asset-name>` redirect (needs the version-embedded asset name anyway).

## 7. Invoking the INSTALLED product headlessly (CLI + DLL for the API path)

- **Installed CLI**: `"C:\Program Files\HeicFast\Recovery Wizard\rrecov.exe"`.
  Verbs: `list`, `list-carve-formats`, `sessions`, `scan`, `tree`, `archive-list`,
  `recover`, `health`, `image`, `fix`, `unlock`, `apply`, `bench` (full usage:
  rrecov.cpp:4082-4154).
  - **Elevation**: every raw-disk verb gates through `require_privilege()` —
    unelevated prints the refusal and **exits 4** (`ERR_ELEVATION_REQUIRED`,
    rrecov.cpp:538-549; usage note rrecov.cpp:4151-4154). `--image` file-backed
    targets and session/report/preview verbs run WITHOUT elevation
    (rrecov.cpp:551-559,545). Run it from an elevated shell on CI (GitHub
    Windows runner shells are elevated).
  - **Working directory**: none assumed for the engine — `userdata-defaults.json`
    is probed exe-adjacent via GetModuleFileNameW (rrecov.cpp:1359-1366), so the
    installed copy loads automatically. The `sessions` verb's default listing dir
    is the CURRENT directory ("." — rrecov.cpp:1115-1116); sessions/reports are
    written where you point them (`--out`, `--autosave-dir`, `--report`).
  - **Exit codes seen**: 0 success; 4 elevation refusal; 1 enumeration/arg errors;
    3 Ctrl-C-cooperative cancel (rrecov.cpp:4078-4081).
- **Installed DLL for an API harness**:
  `"C:\Program Files\HeicFast\Recovery Wizard\cr_ui.dll"` — LoadLibrary it (the
  vcpkg runtime DLLs sit in the same directory). ABI gate: `cr_ui_abi_version()`
  must return `CR_UI_ABI_VERSION` = **4** — the bridge refuses to bind otherwise
  (engine/include/cr/cr_ui.h:81,103; contracts/README.md:50). NOTE: headers and
  `cr_ui.lib` are NOT installed (nsi:251) — build the harness against the in-repo
  header `engine/include/cr/cr_ui.h` and use runtime binding, or take `cr_ui.lib`
  from the portable zip / build stage.
- **Installed UI headlessly**: launch
  `"C:\Program Files\HeicFast\Recovery Wizard\recovery-wizard-ui.exe"` with
  `$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = "--remote-debugging-port=9222"` and
  WorkingDirectory = the exe dir, then drive WebView2 over CDP
  (`http://127.0.0.1:9222/json/version`) — this is the proven forensic pattern
  (tools/forensic/launch-app.ps1:19-47; forensic-repro.yml:141-163). The exe carries
  requireAdministrator (app.manifest:25; D1 build gate build.ps1:188-203) — an
  unelevated CreateProcessWithLogonW start is REFUSED BY THE OS (forensic-repro.yml:
  178-200). When running as a user without a profile, set
  `WEBVIEW2_USER_DATA_FOLDER` to an ACL-granted scratch dir or the WebView2 child
  dies before the first log write (RELEASE-RUN.md, v0.8.4 twin analysis).
- **Where sessions/reports land by default**: the bridge writes sessions to
  `%ProgramData%\HeicFast\Recovery Wizard\sessions\` and logs to `...\logs\`
  (contracts/README.md:47-48; constants defined ONCE there). Recovery reports are
  engine-side JSON via `--report` (CLI) or the in-app report (cr_ui_recovery_report_
  json; INSTALL-FOOTPRINT-DELTA.md:41-42). Recovered FILES go wherever the user chose
  — never touched by uninstall (nsi:592).

## 8. Uninstall behavior — what survives

- **ProgramData sessions are KEPT by default**: interactive uninstall asks with
  default NO; a SILENT uninstall never deletes user data at all — `${If} ${Silent}`
  guard jumps straight to keep-state, and the box itself carries `/SD IDNO`
  (nsi:577-600). Quote: "Silent uninstall: shared state kept (C:\ProgramData\
  HeicFast\Recovery Wizard) — data deletion requires interactive consent."
  (nsi:589). Proven by forensic #29 step 10 on v0.8.4: "uninstaller exit 0, the
  install dir GONE, the uninstall registry key GONE, no service, no driver file;
  ProgramData sessions kept by documented design" (RELEASE-RUN.md:422-427) and by
  t15 row `uninstall(silent) ok {"leftoverFiles":0,"sessionsKept":true}`
  (t15-runtime-matrix.md:11).
- Everything else is removed: kit DLLs (explicit + `*.dll` catch-all, nsi:615-636),
  product + uninstall + seeded registry keys (nsi:639-654), `install.log` +
  `app.log`/`app.log.old` (nsi:661-667), empty dirs (nsi:668-671).

## 9. Build-tree binaries vs installed binaries — what differs for e2e

1. **Paths + structure are the same flat kit** (build.ps1:168-176 stages the kit
   beside `ui\src-tauri\target\release\recovery-wizard-ui.exe`), so loader behavior
   is identical; only the root differs (build tree vs `C:\Program Files\HeicFast\
   Recovery Wizard`).
2. **Portable-mode marker**: build tree and installed builds have NO
   `recovery-wizard.portable` marker → the bridge resolves ProgramData
   sessions/logs; ONLY the portable zip carries the marker → `.\sessions`,
   `.\logs` beside the exe (contracts/README.md:52-61; portable.ps1:73-77). An e2e
   on the build tree writes sessions to ProgramData exactly like the installed
   product; on the portable zip it writes beside the exe.
3. **Signing**: staged `cr_ui.dll`, `rrecov.exe` and the outer setup.exe carry the
   ephemeral dev signature (`CN=HeicFast Recovery Wizard Development Signing`,
   signtool /fd SHA256 — devsign.ps1:60,144-165; build.ps1:140-144,255-258); the
   TAURI APP BUNDLE (`recovery-wizard-ui.exe`, inner setup) is NOT signed — the
   documented production-signing gap; SmartScreen may warn on first run
   (docs/DEV-SIGNING.md:19,71-74; release.yml notes :263-275). The signature is an
   integrity marker, NOT a load prerequisite (docs/DEV-SIGNING.md:31-48).
4. **Curated kit vs build tree extras**: the build tree carries gtest/gmock DLLs
   deployed beside cr_ui.dll; the shipped kit excludes them (build.ps1:105-120) and
   the uninstaller's catch-all exists precisely because kits once leaked them
   (nsi:629-636).
5. **Installed-only files**: inner `uninstall.exe`, `HeicFastUninstall.exe`,
   registry keys, ProgramData dirs, Start Menu shortcuts (§3).
6. **Elevation posture identical** (same exe; D1 gate at build, manifest gate
   re-verified after install — forensic-repro.yml:113-127 reads the installed exe's
   manifest bytes and requires `requireAdministrator`).

## 11. Caveats an e2e job must know

- **Asset names are version-embedded** — always resolve `tag_name` from
  `releases/latest` before constructing URLs (§6).
- **v0.9.4 installer precedent**: a shipped installer CAN abort exit 2 on machines
  other than the build machine; check `%TEMP%\HeicFastRecoveryWizard-install-abort.txt`

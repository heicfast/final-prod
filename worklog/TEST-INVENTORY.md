## 3. THE VHDX FIXTURE MACHINERY (the highest-value reuse)

### 3.1 The named-feature lane, step by step

Lane: `.github/workflows/named-feature-fixture.yml`.

1. **Create+attach VHDX** (fixture job, windows-latest, lines 43-59): inline diskpart script — `create vdisk file=... type=expandable maximum=2048`, `attach vdisk`, `convert gpt`, `create partition primary`, `format fs=ntfs label="NFFX" quick`, `assign letter=X`; success counted by ≥5 "DiskPart successfully" matches (line 58-59). This is the documented "seed-disks.ps1 pattern".
2. **Generate the fixture twice** (lines 61-96): `pwsh tools/validation/named-feature/generate-fixture.ps1 -Root 'X:\' -ManifestOut <m1>`; second generation on the RUNNER SCRATCH DISK (never the evidence VHDX — the D-LANE-01 lesson, lines 62-72); determinism proof = `Compare-Object` over manifest lines skipping `_meta` (lines 88-94).
3. **Apply the deletion matrix** (lines 98-101): `tools/validation/named-feature/apply-deletions.ps1 -Root 'X:\' -ManifestOut <m1> -LogOut apply-log.json`.
4. **Verifier self-test** (lines 103-105): `python tools/validation/named-feature/verify-reconstruction.py --self-test` (5/5).
5. **Flush + detach** (lines 107-119): `Write-VolumeCache -DriveLetter X` then finally-block diskpart `select vdisk` + `detach vdisk`. **Never remounted-and-written afterwards** (the testlab lesson, header lines 9-11).
6. **engine-flow job** (windows-2022, needs fixture, lines 139-244): build rrecov (win-x64-release /W4 /WX) → download the VHDX artifact → **`rrecov scan --image <vhdx> --whole-disk --out scan.crsf`** (line 196) → **`rrecov recover --in session --image <vhdx> --to out --reconstruct-deleted --report recovery-report.json`** (line 204; exit 2 tolerated — "the verifier is the judge", line 207) → complete output listing captured pre-zip (lines 215-219, the run-44475017206 dotfile-evidence lesson) → **`verify-reconstruction.py --manifest manifest.jsonl --out out --report verify-report.json`** (line 225) → PASS verdict I1–I5.

### 3.5 Baked-in operational lessons (do not relearn these)

Each idiom below is already encoded in the scripts — keep them when porting:
- diskpart-only vdisk ops on runners (no Hyper-V module dependency),
  `New-TestDisk.ps1:5-10`;
- disk numbers resolved by BEFORE/AFTER `Get-Disk` diff, never "highest",
  `New-TestDisk.ps1:14-16`;
- drive letters asserted free before assignment (`Test-LetterFree`/
  `Get-FreeLetter`, `New-TestDisk.ps1:61-76`);
- work drive probed at runtime, never hardcoded (`New-TestDisk.ps1:18-22`);
- double flush around deletion + never remount-between-delete-and-scan
  (`tools/validation/named-feature/README.md:56-65`);
- WriteThrough FileStream for any mid-apply cached write (D-V2-DURABILITY,
  `apply-deletions.ps1:110-131`);
- probe/fixture files that must survive as manifest rows are DECLARED rows so
  I4 accountability stays exact (D-PROBE-01,
  `generate-fixture.ps1:114-137`);
- artifacts: bare `**` globs skip dot-prefixed entries — name dotfiles
  explicitly in upload paths (`named-feature-fixture.yml:239-242`);
- $LASTEXITCODE-null asymmetry for cmdlet-only scripts — use `$?`
  (`validation-evidence.yml:208-214`);
- collect-every-result-then-verdict (`EAP=Continue` in the scenario loop,
  `Run-Benchmark.ps1:28-35`).

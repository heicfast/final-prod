# PARITY-DELTAS — divergences from the reference product, with rationale

The reference product's installed layout and install behavior are the
target WHERE OBSERVABLE (corpus: easeus-drw-research). Where the reference
is idiomatic we match; where its choice was idiosyncratic we deviate
deliberately and record it here. No silent divergence.

> below that assumed a kernel transport in our product is REVERSED: the
> driver is removed entirely (commit 318b9655) and the user-mode
> direct-access posture is the product (engine session-96 advance + the

> records inline.

| **D-FALL** | **The driver is MANDATORY — every driver-absent fallback removed** (user directive, 2026-10-27). The reference's Device.mo duality — EPRDTDRV grammar first, silent `\\.\PhysicalDriveN`/`HarddiskVolumeN` direct fallback when the probe fails (`Device_decompiled.c:352-359, 7816-7823, 50653-50660, 52437-52444`) — is DELIBERATELY NOT REPRODUCED. Our engine rides the RDA grammar exclusively; a missing driver is the distinct `ERR_DRIVER_REQUIRED` (0x50020007) refusal naming the remedy. The CLI's `--no-rda` switch is removed; the WinPE direct-open gate is removed (the driver installs on PE media via `driver/scripts/winpe`); the direct-handle transports (`open_physical_drive`/`open_harddisk_volume`/`DirectDevice`/`open_path`) are DELETED. | The user directive supersedes the corpus-observed duality: "driver is the only way, its not optional, its mandatory, so remove any fallbacks for it." Engine-internal corroboration: `engine/docs/DRIVER-UTILIZATION.md` §1.9 (superseded marker), `engine/AUDIT-FALLBACKS.md` rows FB-T01/T02/K04 (class: fallback; disposition changed by this directive). **[REVERSED 2026-11-05 — consolidation session: the driver itself is REMOVED from the product entirely (engine session-96 advance + commit 318b9655).
